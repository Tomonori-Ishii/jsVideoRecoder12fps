# ADR-0004: 中間ファイルは 3 分単位のレコード列にする

- 状態: 承認
- 関連: 要件 F-028、F-038、F-037、Issue #31、#37

## 背景
録画中の符号化データを 3 分ごとに中間ファイルへ書き出す。メモリに 3 分分を保持しない。異常終了時に掃除できるよう、状態を残す。

## 決定
- 保存先は一時フォルダ `<userData>/recordings/<録画ID>/` とする。録画 ID は開始時刻から作る。
- 3 分（180 秒の録画時間）ごとにセグメントファイル `seg-000.bin`、`seg-001.bin`… に切り替える。
- レコードの形式（リトルエンディアン）:
  - ヘッダー 1 バイト: 種別（1 = 映像の符号化データ、2 = 音声の符号化データ、3 = スキップ開始、4 = 停止の印）
  - 時刻: 8 バイト（種別 1・2 は映像の枠番号 `slot` または音声のサンプル位置、3 は枠番号）
  - 長さ: 4 バイト、本体: 可変（種別 1・2 は符号化データ、種別 1 はキーフレーム判定を含むフラグ 1 バイトを本体の先頭に置く）
- レンダラーは符号化データを IPC で送り、メインプロセスが `fs.write` で追記する。フレームごとにファイルを作らない。
- 停止（正常）時は `seg-*.bin` を順に読んで多重化し、完了後に録画フォルダを削除する。
- 状態ファイル `state.json` を録画開始時に作り、正常終了時に削除する（ADR-0010）。

## 結果
- メモリ上には、IPC の一時バッファと書き込み待ち行列の一部だけを置く（要件 F-028）。
- 中間データの大きさは要件 9.3 の見積もり（2 時間で約 1GB）に近い値になる。
