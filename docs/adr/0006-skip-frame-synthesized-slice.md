# ADR-0006: スキップフレームは H.264 の P スライスを合成して表す

- 状態: 承認（実装に合わせて改訂: POC は type 2、スキップ枠は参照ピクチャー）
- 関連: 要件 F-035、F-021、Issue #27、#24

## 背景
同じ画面のフレームは符号化しない（F-035）。一方、mp4 は 12fps の CFR を保つ必要がある（F-021）。mp4 は「同じ内容のサンプル」を参照で表せないため、ビットストリーム上で「直前の枠をそのまま使う」フレームを表す必要がある。

## 決定
- 中間ファイルにはスキップ開始の印（種別 3）だけを書く（F-035 の「1 件だけ」）。
- 多重化時、符号化されていない枠には「全マクロブロックがスキップの P スライス」を合成して 1 サンプルとして書く（`electron/recording/h264.cjs` の `buildSkipSliceNal`）。
- **全ての枠を参照ピクチャーにする。** スキップ枠は `nal_ref_idc = 1` とする。POC の種類は 2（`pic_order_cnt_type = 2`）とし、POC は frame_num から決まる。Electron の符号化器（OpenH264）が出す SPS も type 2 だった。
- frame_num は枠番号から決める: `frame_num = (枠番号 − 直近の IDR の枠番号) mod MaxFrameNum`。符号化済みの枠も、多重化時にスライスヘッダーの frame_num を書き換える（桁数が変わらないためビットの上書きで済む）。IDR は 0。
- 符号化の PPS が CABAC の場合、スキップ合成は行わず、録画は失敗として扱う（ADR-0003 の方針の範囲）。実際には CAVLC のため未発生。
- 検証: `tests/unit/mux-skip.test.js` で、libx264 の CAVLC 映像を使い、スキップ枠のデコード結果が直前の枠と完全に一致することを確かめる。E2E（静止画面）でも、実際の録画パイプラインで同じ性質を確かめる。

## 改訂の理由
当初案は POC type 0 を前提に、符号化済みの枠の POC 下位ビットを書き換える設計だった。実際の符号化器は POC type 2 を出すため、type 2 を前提にする方が単純で、非参照の連続（type 2 で禁止される）も起きない。

## 制約
- 合成したビットストリームが仕様どおりでない場合、再生できないフレームが出る。デコード検証で必ず確認する。
- 重み付き予測、スライスグループ、CABAC は対応しない（例外にする）。
