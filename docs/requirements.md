## 1. はじめに

### 1.1 目的

画面と音声を、ファイルに記録する小型のデスクトップアプリを作る。利用者は、開始・一時停止・再開・停止の 4 つの操作だけで記録する。

### 1.2 用語

| 用語 | 定義 |
|---|---|
| 録画 | 開始から停止までの記録操作全体。プライマリ画面の映像と、マイクおよびスピーカーの音声を記録する。 |
| 待機中（`idle`） | 録画を開始していない状態。停止処理の後を含む。 |
| 録画中（`recording`） | 録画を開始し、一時停止も停止もしていない状態。 |
| 一時停止中（`paused`） | 録画を一時停止している状態。 |
| 停止処理中（`stopping`） | 停止後、保存ファイル（mp4）を作成している状態。 |
| 経過時間 | 一時停止の時間を除いた、録画の長さ。 |
| 音量 | 直近約 50ms の音声の実効値（RMS）を dB で表した値。 |
| 中間ファイル | 録画中に符号化データを順に書き出す一時ファイル。 |
| 多重化 | 符号化した映像と音声を、mp4 コンテナにまとめる処理。再符号化は含まない。 |
| スキップフレーム | 直前のフレームと同じ映像を、符号化せずに参照で表すフレーム。 |
| CFR | 一定のフレームレート（Constant Frame Rate）。 |
| プライマリ画面 | OS で主となるディスプレイ。 |

## 2. システム概要

### 2.1 システム構成

```
┌──────────────────────── Electron ────────────────────────┐
│ メインプロセス（electron/main.cjs）                        │
│  - 窓の生成（292×80px。録画中は映像から除外）                │
│  - 権限の制御（media、display-capture）。選択画面は出さない   │
│  - 対象画面の指定（プライマリ画面の ID）                     │
│  - 中間ファイルへの書き込み（3 分単位）                      │
│  - 空き容量の監視（30 秒ごと）                              │
│  - 多重化（停止時。.partial → .mp4）                       │
│  - 起動時の掃除（state.json を読む）                        │
│        ▲ preload（contextBridge。公開する API は 7.2 の表のみ）│
│        ▼                                                    │
│ レンダラー（src/）                                          │
│  - 画面の取得（getDisplayMedia。12fps の時刻ごとに 1 枚）     │
│  - 映像の符号化（VideoEncoder、H.264。HW 優先、なければ CPU）  │
│  - 音声の混合（マイクとスピーカー。モノラル、Opus）            │
│  - 音量の表示（混合した音声のレベル）                        │
│  - 表示（経過時間、進み具合、エラー）                       │
└────────────────────────────────────────────────────────────┘
```

- 符号化データは、レンダラーで生成し、メインプロセスが中間ファイルへ書き込む。
- 映像は `Blob` を作らない。mp4 は、メインプロセスがファイルへ直接書き込む。

### 2.2 スコープ

#### 対象

- Electron 45 のデスクトップアプリ。開発環境で起動して使う（配布物は作らない）。
- 録画の操作（開始、一時停止、再開、停止）。
- マイクの選択、音量と経過時間の表示。
- 映像と音声の録画（プライマリ画面、12fps、H.264 の mp4、音声はマイクとスピーカー）。
- 対象 OS は Linux と Windows とする。

#### 対象外

- 音声の再生。
- 保存先を選ぶダイアログ。保存先は Downloads に固定する。
- mp4 以外の映像形式。
- 画面の選択。将来対応とし、今はプライマリ画面を固定で対象にする。
- フレームレートの変更手段（コマンドラインやメニュー）。将来対応とし、今は既定値 12fps を使う。
- インストーラーなどのパッケージ化。
- macOS への対応。将来検討とする。
- エコーキャンセル、ノイズ抑制、自動音量調整。
- 録画の復旧。異常終了や容量不足で止まった録画は、視聴できない。

### 2.3 前提と制約

- 操作は「開始」「一時停止」「再開」「停止」の 4 つに限る。
- 停止すると、Downloads フォルダに自動で保存する。保存先のダイアログは表示しない。
- サーバーを使わず、すべての処理をアプリ内で行う。ネットワークは使わない。
- UI は React で実装する。
- マイクの使用には、OS とアプリの許可が必要である。
- 配布用の署名、インストーラー、macOS のマイク使用説明（`NSMicrophoneUsageDescription`）は対応しない。

## 3. 操作と状態

### 3.1 操作

| 操作 | ボタン | 実行できる状態 | 結果の状態 |
|---|---|---|---|
| 開始 | ● | `idle` | `recording` |
| 一時停止 | ❚❚ | `recording` | `paused` |
| 再開 | ▶ | `paused` | `recording` |
| 停止 | ■ | `recording`、`paused` | `stopping` |
| ミュート切り替え | マイクのアイコン | `recording`、`paused` | 状態は変わらない |

### 3.2 状態遷移

| 状態 | 意味 | 次の状態 |
|---|---|---|
| `idle` | 待機中 | `recording`（開始） |
| `recording` | 録画中 | `paused`（一時停止）、`stopping`（停止）、`stopped-space`（空き容量の不足） |
| `paused` | 一時停止中。映像と音声を記録しない。 | `recording`（再開）、`stopping`（停止） |
| `stopping` | 停止処理中。mp4 を作成する。 | `saved`（成功）、`failed`（失敗） |
| `saved` | 保存が完了した。 | `idle` |
| `failed` | mp4 の作成が途中で失敗した。 | `idle`（次回起動時に掃除） |
| `stopped-space` | 空き容量の不足で止めた。mp4 は作成しない。 | `idle`（次回起動時に掃除） |

- 一時停止中は、一時停止ボタンの表示を ▶（再開）にする。
- `stopping`、`stopped-space`、`failed` の録画は、視聴の対象としない。

## 4. 操作・入力・表示の機能要件

各機能の受け入れ条件は、ここに書いた数値と文言で判定する。

### 4.1 録画操作

#### F-001 録画を開始する（must）

- 開始ボタンを押すと、選択中のマイクから録画を始める。
- 録画中は経過時間が進む。
- 録画中は開始ボタンを無効にし、一時停止ボタンと停止ボタンを有効にする。
- 開始処理の途中で開始ボタンを押されても、録画を二重に始めない（F-015）。

#### F-002 一時停止する（must）

- 録画中に一時停止ボタンを押すと、録画を止める。
- 一時停止中は経過時間を進めない。
- 一時停止中は音量バーを 0%、dB 表示を `-60.0 dB` にする（F-006）。
- ボタンの表示を ▶（再開）に変える。

#### F-003 再開する（must）

- 一時停止中に再開ボタンを押すと、同じファイルに続けて録画する。
- 経過時間は、一時停止の前の値から続けて進む。

#### F-006 一時停止中は音量を 0 にする（must）

- 一時停止に入ると、音量バーを 0%、dB 表示を `-60.0 dB` に戻す。

#### F-015 開始ボタンの連打を防ぐ（should）

- 開始処理の途中、または録画中に開始ボタンを押されても無視する。録画は二重に始まらない。

#### F-017 停止処理の失敗に対応する（should、未実装）

- 停止処理が失敗しても、画面が録画中のまま止まらないようにする。
- エラーを画面に表示し、マイクと音声処理を解放して、次の録画を開始できる状態に戻す。
- 受け入れ条件: 失敗時にエラーが表示される。ボタンが初期状態に戻る。マイクと `AudioContext` が解放される。次の録画を開始できる。

#### F-018 一時停止・再開ボタンの連打を防ぐ（should、未実装）

- 一時停止または再開の処理の途中で、同じボタンを押されても二重に処理しない。
- 受け入れ条件: 処理中の操作は無視される。状態が食い違わない。処理後、ボタンが次の操作を受け付ける。

### 4.2 入力と音量

#### F-005 音量をバーと dB で表示する（must）

- 録画中の音量を、0〜100% のバーと dB の数値で表示する。録画中は、マイクとスピーカーを混ぜた音声のレベルを表示する。
- dB の範囲は −60.0〜0.0 とし、小数点以下 1 桁で表示する（例: `-17.6 dB`）。
- バーの割合は `(dB + 60) / 60 × 100` を 0〜100 に収めた値とする。
- 更新間隔は約 100ms とする。
- バーの色は灰色 1 色とする。

#### F-007 マイクを選択する（must）

- 利用できる音声入力デバイスを、画面のプルダウンに一覧表示する。
- 録画中と一時停止中は、選択を変更できない。
- マイクの接続と切断に合わせて一覧を更新する（`devicechange` イベント）。

#### F-008 起動時にマイク許可を求める（should）

- 起動時に一度マイクの使用を要求し、デバイス名（ラベル）を表示できるようにする。
- 許可されない場合、デバイス名は表示されない。

#### F-013 マイクをミュートする（should）

- 録画中と一時停止中に、ミュートボタンでマイクの音を止める。
- ミュート中は無音として記録し、時間軸は保つ。スピーカーの音は変えない。
- 録画を開始するたびに、ミュートを解除した状態で始める（Issue #3）。

### 4.3 表示と通知

#### F-004 経過時間を 100ms 単位で表示する（must）

- 形式は `h:mm:ss.t` とする。`h` は時（常に表示）、`mm` と `ss` は 2 桁、`t` は 100ms の 1 桁（切り捨て）とする。
- 例: `0:00:00.0`、`0:01:02.7`
- 更新間隔は約 100ms とする。
- 一時停止中は値を変えない。

#### F-009 エラーを画面に表示する（must）

エラー名ごとに、次のメッセージを画面下部に 1 行で表示する。

| エラー名 | 表示するメッセージ |
|---|---|
| `NotAllowedError`、`SecurityError` | マイクの使用が許可されていません。OSやアプリのマイク設定を確認してください。 |
| `NotFoundError`、`OverconstrainedError` | マイクが見つかりません。マイクを接続してから再度お試しください。 |
| `NotReadableError`、`AbortError` | マイクを使用できません。他のアプリがマイクを使用していないか確認してください。 |
| その他 | エラーが発生しました: <メッセージ> |

- デバイスが 1 つもない場合は、「マイクが見つかりません。マイクを接続してください。」と表示する。
- 表示しきれない部分は末尾を `…` で省略する。全文は `title` 属性（マウスオーバー）で確認できる。

#### F-010 保存完了を画面に表示する（should）

- 停止後、保存中は「保存しています…」と表示する。進み具合（F-036）を表示する場合は「保存しています… NN%」とする。
- 保存が完了したら「保存しました: <絶対パス>」に変える。例: `保存しました: /home/<ユーザー>/Downloads/screen_20261119_143025.mp4`
- 絶対パスが画面幅に収まらない場合は、横にスクロールして流す（ティッカー表示）。収まる場合は流さない。
- メッセージ（ティッカーを含む）は、保存後に表示する。録画中と一時停止中は、エラーを除きメッセージを表示しない。
- Electron 以外（ブラウザでの表示）では、保存中の表示を出さず、「<ファイル名> を保存しました」と表示する。

#### F-011 操作ボタンをアイコンで表示する（must）

- 開始は **●**、一時停止は **❚❚**、再開は **▶**、停止は **■**、ミュートは **マイクのアイコン**（ミュート中は斜線）で表示する。
- 各ボタンの大きさは 30×20px とする。
- 各ボタンに `aria-label` と `title` を付ける（開始、一時停止／再開、停止、ミュート）。

#### F-012 動作状態のラベルを表示しない（must）

- 「待機中」「録画中」「一時停止中」の文字は表示しない。
- 状態は、ボタンの有効・無効と、経過時間の動きで示す。

#### F-016 日本語で表示する（should）

- 画面の文言（ボタンの `aria-label`、メッセージ、マイク名の既定表示）は日本語とする。
- `index.html` の `lang` は `ja`、`title` とウィンドウのタイトルは「Video Recoder」とする。

## 5. 録画の機能要件

録画は、第 4 章の操作ボタン（開始、一時停止、再開、停止）をそのまま使う。出力は映像付きの mp4（F-030）だけとする。

### 5.1 録画の基本

#### F-019 画面を録画する（must）

- 開始ボタンを押すと、映像と音声の録画を始める。
- 一時停止、再開、停止は、映像と音声の両方に作用する（F-002、F-003）。
- 停止すると、映像付きの mp4 を Downloads フォルダに保存する（F-029、F-030）。
- 録画中は経過時間（F-004）で録画中であることを示す。録画中専用の表示は設けない。
- 受け入れ条件: 開始で映像と音声の録画が始まる。停止で mp4 が保存される。

#### F-020 映像に音声を含める（must）

- mp4 には、次の 2 つの音声を含める。
  - マイク入力（選択中のマイク、F-007）
  - スピーカーのライン入力（システムの出力音）
- 2 つの音声は、モノラル 1 つのトラックにまとめる。
- 音声の形式は Opus、48kHz、128kbps とする。
- 受け入れ条件: mp4 に音声トラックがあり、マイクの音とスピーカーの音の両方が含まれる。

#### F-023 マウスカーソルを映像に含めない（must）

- 映像にマウスカーソルを含めない。
- 受け入れ条件: 録画した映像にカーソルが映らない（確認は 8.3 の手順で行う）。

#### F-025 録画ウィンドウを映像から除外する（must）

- 録画中、アプリ自身の窓（292×80px）を映像に映さない。
- 受け入れ条件: 録画した映像に、アプリの窓が映らない。

#### F-026 プライマリ画面を録画する（must）

- 録画の対象は、プライマリ画面（全画面）の 1 つだけとする。
- 画面は内部で画面 ID により指定する。今はプライマリ画面の ID を固定値で指定する（4.2 の将来対応に備える）。
- 受け入れ条件: 録画の対象が、プライマリ画面の ID で指定されている。

#### F-031 画面収録の権限を求め、拒否時にエラーを表示する（must）

- 画面を録画するため、OS とアプリの画面収録の権限を要求する。
- 権限が拒否された場合は、次のメッセージを表示する（F-009 の形式に従う）。
  - 「画面の録画が許可されていません。OSやアプリの画面収録の設定を確認してください。」
- 受け入れ条件: 権限が拒否されると、そのメッセージが表示され、録画は始まらない。

### 5.2 映像の仕様

#### F-021 映像を 12fps の CFR にする（must）

- 映像のフレームレートは 12fps の固定（CFR）とする。
- 撮影が間に合わないフレームは落とす。フレームの複製と補間は行わない。
- 受け入れ条件: `ffprobe` でフレームレートが 12fps と判定される。
- 例外: CPU 使用率の上限を超えそうな場合は、フレームレートを下げてよい（7.4）。

#### F-022 映像の形式を H.264 の mp4 にする（must）

- コーデックは H.264（`avc1`）、コンテナは mp4 とする。
- 解像度は 1920×1080px とする。画面の縦横比が 16:9 でない場合は、縦横比を保って収め、余白は黒とする。
- ビットレートは約 1Mbps（可変。目標値）とする。
- 符号化は録画中に行う（F-034）。停止時に再符号化しない（F-029）。
- 受け入れ条件: `ffprobe` でコーデックが H.264、解像度が 1920×1080、ビットレートが約 1Mbps（目標値）である。

#### F-032 フレームレートを設定値にする（should）

- フレームレートは 1〜30fps の範囲で設定できる設定値とする。既定値は 12fps とする。
- 今回は既定値のみを使う。変更手段は将来対応とする（2.2）。
- 受け入れ条件: 既定値が 12 である。範囲外の値は使われず、既定値に戻る。

#### F-035 同じ画面のフレームを保存しない（must）

- 直前のフレームと同じ画面（縮小後の画素が一致）のフレームは、符号化しない。代わりに、直前のフレームを参照するスキップフレームとして中間ファイルに記録する。
- 同じ画面が続く間、以降のフレームは符号化も記録もしない。
- 停止時の多重化では、その時刻に直前のフレームを参照するスキップフレームを置く。映像は 12fps の CFR を保つ（F-021）。
- 受け入れ条件: 同じ画面が続くとき、中間ファイルへの記録はスキップ指示の 1 件だけになる。mp4 は `ffprobe` で 12fps と判定される。一時停止と再開をはさんでも、映像が正しく再生される。

### 5.3 時間の扱い

#### F-024 一時停止中の映像と音声を記録しない（must）

- 一時停止の間は、映像と音声を記録しない。
- 再開すると、停止していた時間を除いて続けて記録する。映像と音声の時刻は、録画開始を 0 として詰める。
- 映像の時刻は、12fps のフレーム番号（フレーム番号 ÷ 12 秒）で決める。
- 経過時間（F-004）と映像の長さが一致する。
- 受け入れ条件: 一時停止をはさんだ録画の mp4 の長さが、停止時間を除いた経過時間と一致する。

#### F-027 録画時間の上限を 2 時間にする（must）

- 録画時間の上限は 2 時間とする。
- 2 時間に達したら録画を自動で止め、ここまでの映像と音声を保存する。保存完了の表示（F-010）と、上限に達したことを示すメッセージを表示する。
- 受け入れ条件: 2 時間で録画が止まり、mp4 が保存される。

### 5.4 符号化と中間ファイル

#### F-034 符号化をハードウェアで行い、使えないときは CPU で行う（must）

- H.264 の符号化は、ハードウェア符号化が使えるときはそれを使う。
- ハードウェア符号化が使えないときは、CPU（ソフトウェア符号化）で録画中に符号化する。この場合は CPU 使用率の上限（7.4）を守る。上限を超えそうな場合は、フレームレートを下げる。
- 使った方式（ハードウェアかソフトウェアか）を、録画ごとに記録する。
- 受け入れ条件: ハードウェア符号化が使えない環境でも録画が完了する。使った方式が記録される。録画中の CPU 使用率が 10% 以下である。

#### F-028 3 分単位で中間ファイルに書き出す（must）

- 録画中に符号化した映像（H.264）と音声（Opus）は、3 分ごとに中間ファイルへ書き出す。
- 中間ファイルには、時刻つきの符号化データを順に並べる。フレームごとにファイルを作らない。
- メモリには、符号化の出力と待ち行列の一部だけを置く。3 分分をまとめて保持しない。
- 中間ファイルは、停止して保存が完了するまで残す。保存が完了したら削除する。
- 受け入れ条件: 録画中、メモリ上の映像データが 3 分分を超えない。3 分ごとに中間ファイルが切り替わる。保存完了後に中間ファイルが削除される。

### 5.5 停止と保存

#### F-029 停止時に mp4 を作る（must）

- 停止時は、中間ファイルの符号化データを mp4 に多重化する。H.264 の再符号化は行わない。
- 作成した mp4 を Downloads フォルダに保存する。保存先のダイアログは表示しない。
- 書き込み中の mp4 は `screen_<時刻>.mp4.partial` とし、完了したら `.mp4` に変える。
- 録画を視聴の対象とするのは、多重化が成功した録画だけとする。
- 多重化が途中で失敗した場合（空き容量の不足、書き込みエラーなど）は、`.partial` を削除する。中間ファイルは残し、次回起動時の掃除で削除する。
- 受け入れ条件: 停止後に mp4 が Downloads に保存される。映像の符号化は録画中に行われ、停止時に再符号化しない。保存後に中間ファイルが削除される。

#### F-030 映像のファイル名を付ける（must）

- ファイル名は `screen_YYYYMMDD_HHMMSS.mp4` の形式とする。時刻は録画開始時のローカル時刻とする。
- 例: `screen_20261119_143025.mp4`
- 一時停止と再開をしても、ファイル名は変わらない。

#### F-036 停止時の進み具合を表示する（must）

- 停止から mp4 の作成までの間、進み具合を割合（%）で表示する。表示は「保存しています… NN%」の形式とする（F-010）。
- 割合は、多重化したサンプルの量（時間）を、録画全体の量で割って求める。
- 表示は約 0.5 秒ごとに更新する。完了後は「保存しました: <絶対パス>」に変える（F-010）。
- 受け入れ条件: 停止中に割合が増える。完了すると保存完了の表示に変わる。

### 5.6 容量と異常時の扱い

#### F-033 空き容量を確認する（must）

- 録画を始める前に、中間ファイルを置く場所の空き容量を確認する。空き容量が 3GB 未満の場合は、録画を始めない（9.1 の仮の値）。
- 録画中は 30 秒ごとに確認する。空き容量が「現在の中間データの大きさ ＋ 0.5GB」を下回った場合は、録画を止め、中間ファイルを残す（9.1 の仮の値）。
- 録画を止めた場合は、「空き容量が不足したため録画を止めました」と画面に表示し、中間ファイルの場所（絶対パス）を示す。
- 空き容量の不足で止める場合は、システムの安定性を優先する。mp4 は作成せず、ディスクへの追加の書き込みは行わない。
- 通常の停止後、空き容量が「中間データの大きさ ＋ 0.2GB」以上ある場合だけ mp4 を作成する（9.1 の仮の値）。不足する場合は mp4 を作成せず、中間ファイルを残す。
- 受け入れ条件: 空き容量が足りない場合は録画が始まらない。録画中に不足した場合は、mp4 を作成せずに録画を止め、中間ファイルを残す。通常の停止で容量が足りない場合も、mp4 を作成せず中間ファイルを残す。

#### F-037 容量不足で止めた録画の場所を示し、次回起動時に掃除する（must）

- 容量の不足で録画を止めた場合は、中間ファイルの場所（F-033）を画面に表示する。
- 次回起動時に、前回の中間ファイルを削除する。
- 容量の不足で止めた録画は mp4 にならないため、次回起動時の掃除で削除され、視聴できなくなる。
- 受け入れ条件: 録画を止めたときに場所が表示される。次回起動時に、前回の中間ファイルが削除される。

#### F-038 異常終了のときは中間ファイルを削除する（must）

- 録画中にアプリが正常に終了しなかった場合（クラッシュ、電源断など）は、次回起動時に中間ファイルを削除する。
- 途中まで書き込んだ mp4（`.partial`）も、次回起動時に削除する。
- 異常終了した録画は mp4 にならず、視聴できない。
- 正常に停止し、保存が完了した場合は、F-028 に従い中間ファイルを削除する。
- 受け入れ条件: 録画中に強制終了し、次回起動すると中間ファイルと `.partial` が削除される。

## 7. 非機能要件

### 7.1 性能

- 経過時間と音量の更新間隔は、F-004 と F-005 に従う。

### 7.2 セキュリティ

- `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true` とする。
- 許可する権限は、マイク（`media`）と画面収録（`display-capture`、および画面の取得に必要な `media`）だけとする。それ以外の権限は拒否する（F-031）。
- 外部の URL は読み込まない。`dist/index.html` だけを読み込む。
- preload（contextBridge）が公開する API は、次の表の録画に必要なものだけとする。ファイルの読み書きや任意の IPC は公開しない。

| 方向 | 公開する API | 用途 |
|---|---|---|
| レンダラー → メイン | 録画の開始と停止の通知 | F-019、F-029 |
| レンダラー → メイン | 符号化データの送信（映像と音声。時刻つき） | F-028 |
| レンダラー → メイン | スキップフレーム指示の送信 | F-035 |
| メイン → レンダラー | 保存完了の通知（`onSaved`） | F-010 |
| メイン → レンダラー | 進み具合の通知 | F-036 |
| メイン → レンダラー | 通知（エラー、容量不足、2 時間の上限） | F-009、F-027、F-033 |

### 7.3 互換性

- Electron 45.4.1、React 19.3.1、Vite 8.3.8 を使う。
- Node.js は 22.12 以上を要する（Electron 45 と依存パッケージの要件）。
- 検証環境は Linux（arm64）とする。Node.js 20.19.2 でもビルドとテストは成功したが、起動は Node.js 22.12 以上を前提とする。
- 録画の対象 OS は Linux と Windows とする。macOS は将来検討とする（2.2）。

### 7.4 録画時の CPU 使用率

- 録画中の CPU 使用率は 10% 以下とする。
- この上限は録画中に適用する。CPU で符号化する場合は、この上限を優先する（F-034）。停止時の多重化（再符号化なし）には適用しない。
- 上限を超えそうな場合は、フレームレートを 12fps より下げてよい（F-021 の例外）。映像の品質よりも、この上限を守ることを優先する。
- 受け入れ条件: 録画中の CPU 使用率を計測し、10% 以下であることを確認する（8.3）。

### 7.5 アクセシビリティ

- 各操作ボタンに `aria-label` を付ける。
- 音量バーは `role="meter"` と `aria-valuemin`、`aria-valuemax`、`aria-valuenow` を持つ。
- 動きを減らす設定（`prefers-reduced-motion`）が有効な場合は、ティッカーを流さない。

### 7.6 可用性と保存

- ネットワークを使わず、オフラインで動作する。
- 保存先は Downloads に固定する。同名のファイルは上書きされる（9.3）。

## 8. 検証要件

### 8.1 テスト方針

| 種類 | 対象 | 方法 |
|---|---|---|
| 静的検査（pytest） | 権限、preload の公開範囲、窓の寸法、録画の経路 | `tests/` に追加する（実装時） |
| 単体テスト（JavaScript） | コンテナの書き込みと読み込み、スキップフレームの判定、状態の遷移、掃除 | 導入を検討する（9.1） |
| E2E（Electron） | 録画の開始、一時停止、停止、保存、進み具合 | フェイク画面とフェイクマイクで操作する |
| 成果物の検査（ffprobe） | フレームレート 12、H.264、1920×1080、長さの一致、音声トラック、再生 | `ffprobe` で確認する |
| 負荷の検査 | 録画中の CPU 使用率、停止時の時間 | 計測して記録する |
| 空き容量の検査 | 3 つの判定と、停止の動作 | 容量を変えられる仮想ディスクで確認する |

### 8.2 自動テスト（pytest）

- ソースの記述を確認する静的検査と、`vite build` の実行を含む。

### 8.3 Electron での確認（E2E）

- フェイクマイクで起動する: `--use-fake-device-for-media-stream --use-fake-ui-for-media-stream`
- DevTools（リモートデバッグ）から操作し、次を確認する。
  - 開始、一時停止、再開、停止の各ボタンが、状態どおりに動作する。
  - 停止後、「保存しています…」から「保存しました: <絶対パス>」に変わる。
- 録画（F-019〜F-036）は、録画した mp4 を `ffprobe` で確認する。
  - フレームレートが 12fps（F-021）。コーデックが H.264、解像度が 1920×1080、ビットレートが約 1Mbps（F-022）。
  - 長さが、一時停止を除いた経過時間と一致する（F-024）。
  - 音声トラックがあり、マイクとスピーカーの音が含まれる（F-020）。
  - 再生できる（F-019）。映像にアプリの窓とカーソルが映らない（F-023、F-025）。
  - 録画中の CPU 使用率が 10% 以下である（7.4）。ハードウェア符号化の有無を記録する（F-034）。
  - 同じ画面が続いたときも、mp4 が 12fps と判定される（F-035）。
